# Governance pack

This is lab material for how an Australian insurer would govern a contact centre platform moved to a cloud provider. It is a **design aid and interview aid**. It is not legal advice and it is not a statement that any real organisation complies with anything.

**Items marked (verify)** are details I could not check against the current text of the law, standard or contract while building this. Check them against the source before relying on them.

| File | Purpose |
|---|---|
| `compliance-matrix.md` | Obligation, what it asks, what this design does, evidence, status |
| `threat-model.md` | What can go wrong in the integration layer and the control for each |
| `incident-runbook.md` | Outage, data incident and catastrophe-mode procedures with clocks |
| `service-provider-register-entry.md` | A template entry for a material service provider |
| `raci.md` | Who does what: insurer, carrier, platform vendor, integrator |
| `data-flow-and-residency.md` | Where personal information goes and where it is kept |
| `dr-and-bcp.md` | Recovery objectives and the rehearsal plan |
